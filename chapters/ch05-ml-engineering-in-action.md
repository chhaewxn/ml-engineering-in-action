### 5.1 실험 계획 수립

**실험은 순서대로 진행해야 하며, 단계를 건너뛰면 시간이 더 걸림**

- "계획 수립 → EDA → 프로토타이핑 → 평가" 순서
- 모델을 만들기 전에 반드시 데이터를 **시각화**하고 **통계적 특성**을 파악해야 함
- 데이터 특성 파악 없이 바로 모델링에 들어가면 **불필요한 시행착오**가 늘어나 MVP 납기가 지연됨
- EDA 단계에서 해야 할 4가지 질문 
    1. 데이터가 안정적인가
    2. 계절성이 있는가
    3. 잠재 요인이 추세에 영향을 주는가
    4. 확장성 문제는 없는가
---

**블로그 코드를 그대로 복사해서 쓰지 말 것**

- 블로그는 **간결함**을 목적으로 작성되어 실제 운영 환경에 필요한 세부 사항이 **대부분 생략**되어 있음
    - 기본 하이퍼파라미터만 사용, 데이터 분할 방식 부적절, 평가 지표 부족 등
- 블로그의 올바른 활용법: 새 개념을 접하고 대안적 접근 방식을 탐색하는 용도로만 사용
- 블로그 대신 읽어야 할 것: **API 공식 문서**, 학술 논문, 해당 주제의 도서

---

**API 문서를 반드시 읽어야 하는 이유: 기본값(Default)은 플레이스홀더일 뿐**

- 대부분의 ML Algorithm은 **기본 하이퍼파라미터**가 일반적인 데이터에 맞춰져 있을 뿐, 내 데이터에 최적은 아님
- 어떤 옵션이 있고, 어떤 용도로 사용되며, 어떤 값을 조정해야 하는지 **파악**해야 모델을 제대로 제어할 수 있음
- API 문서를 읽지 않으면 Overfitting되거나, 입력 변동에 지나치게 취약한 모델을 만들 위험이 있음
- 전체 패키지 소스 코드를 리버스 엔지니어링할 필요는 없고, 사용할 클래스의 매개변수와 메서드 수준까지만 숙지

---

**초기 프로토타입 테스트에서는 정확도가 아닌 **속도**에 집중해야 함**

- 이 단계의 목적: 9가지 후보 중 실행 가능한 **1~2개로** 추리는 것
- 하이퍼파라미터 튜닝은 이 단계에서 하지 않음. 기본값으로 돌려보고 대략적인 민감도만 측정
- 단, 기본값을 사용했다는 사실을 코드에 명시적으로 표기하거나 TODO를 남겨야 MVP 단계에서 누락 없이 튜닝 가능

---

**실험은 사내 해커톤 방식으로 운영하고, 공정한 경쟁 환경을 만들어야 함**

- 규칙 설정이 핵심:
    - 모든 팀원이 **동일한 데이터셋, 동일한 평가 지표, 동일한 예측 기간**을 사용
    - 시각화를 지표와 함께 저장하고, 실험 코드로 재연 가능해야 함
    - 테스트 기간에 마감 기한을 두어 긴박감을 조성
- 담당자 지정 없이 "모두가 최고의 솔루션을 찾아라"고 하면 중복 작업과 과도한 노력이 발생

---

**평가 지표는 가능한 한 많이 수집해두되, 팀이 합의한 기준 지표를 하나 정해야 함**

- 실험 단계에서 하나의 지표만 수집하면, 나중에 다른 지표로 전환할 때 이전 실험을 재실행해야 함
- 비용이 낮은 지표(MAE, MSE, RMSE, MAPE, R-squared 등)는 전부 수집해두는 것이 효율적
- 단, 계산 비용이 매우 큰 지표(예: 대규모 데이터셋의 NDCG 등)는 꼭 필요한 경우에만 계산
    - NDCG(Normalized Discounted Cumulative Gain)는 추천/검색 결과의 순서 품질을 측정하는 지표로, "상위에 관련성 높은 항목이 올수록 높은 점수"를 부여함.
    - 계산 비용이 큰 이유는 각 사용자마다 전체 아이템 후보에 대한 예측 점수를 산출하고 랭킹을 생성해야 하기 때문에, 사용자 100만 x 아이템 10만 규모에서는 1,000억 건의 추론이 필요함
- 지표 선택에 대한 논쟁으로 시간을 낭비하지 말 것. 일단 다 수집하고 나중에 논의

## 5.2 실험 사전 준비 작업

**실험적 테스트를 준비하는 것을 잊지 말아야 함**

- 확실한 계획, 합의된 지표, 진행사항 등을 준비하자
- 데이터셋을 자세히 분석하고, 공통된 Tool을 정해야 함
- 모델, 언어, 플랫폼 등을 통일하고, 데이터를 이해하자

---

**분석단계와 프로토타이핑 작업을 위해 평가에 초점을 두어야 함**

- 평가에 초점을 두고 계획을 수립하면 원하는 결과가 나옴

---

**Time-Series Trend 시각화는 데이터의 심각한 결함을 미리 발견할 수 있음**

- Trend 변화를 반영하지 않을 때 생길 수 있는 잠재적 문제를 이해하는데 유용함

---

**디키-풀러(Dickey-Fuller) Stationary test으로 시계열 데이터의 비정상성을 확인하자**

```python
from statsmodel.tsa.stattools import adfuller
dickey_fuller_test = adfuller(jfk_asc['Domestic Passengers'], autolag='AIC')
```

- 해당 test는 Statinarity 여부를 p-value를 통해서 알려주고, LAG값을 자동으로 알려줌
- 하지만 해당 LAG를 믿지 말고 **직접 trend 분석**을 하여 Non-stationary를 제거해야함
- 이는 테스트 단계를 더욱 빠르게 진행할 수 있게함

---

**Time-Series 예측 시스템은 완벽하지 않으며, 이를 꼭 알려야 함**

- Trend가 매우 복잡하거나, 모델링 비용이 과도하거나, 예측 불가한 미지수가 많음

---

**Plot을 만들어 공유할 때는 항상 Raw 데이터를 가장 위에 보여줘야 함**

- 그렇지 않다면 나중에 데이터를 설명하기 위해 복잡한 추가 장표를 만들어야 할 수 있음

---

**함수를 이용하여 재사용이 가능한 코드로 만들어야 함**

- 코드가 깔끔해지고, 팀 전체의 코드가 동일해져 유지 관리가 편해짐
- 의사 결정 시간을 단축함
- 혼란의 여지를 줄이고, 프로젝트에 대한 믿음을 극대화함
- 최종적으로 함수를 모듈화하고, 운영 단계로 배포할 수 있도록 함

---

**“문자열 보간(Interpolation)과 친해지세요”**

| 방식 | 설명 | 주 코드 방법 | 
| --- | --- | --- |
| 게으른 방식(Lazy) | 오류가 발생하기 쉽고, 공백 넣기를 잊어버릴 가능성이 큼 | 연결 연산자 | 
| 문자열 보간(Interpolation) | 유지 보수성이 좋아짐 | ‘{}’.format() 구문 / f-string |

```python
axes[1].set(title=series_name + ' Monthly diff of ' + series_column) # Lazy
axes[1].set(title='{} Monthly diff of {}'.format(series_name, series_column)) # interpolation
```

**Time-Series에서 살펴봐야할 것**

1. Trend Decomposition plotting
2. Outlier plotting
3. autocorrelation과 partial autocorrelation plotting

---

**Autocorrelation과 partial autocorrelation을 둘 다 봐야하는 이유**

- AutoCorrelation (ACF)
    - ‘현재 시점과 과거 시점의 전체적인 닮은꼴 찾기’
    - ACF는 중간 과정을 모두 포함함
    - 즉, LAG 측정에 대한 직접적인 의존성 정보뿐만 아니라 간접적인 효과도 포함됨
    - 따라서 해석을 다소 잘못할 수도 있음
- Partial AutoCorrelation (PACF)
    - PACF는 중간 단계를 제외하고 오직 LAG에 따른 두 시점의 관계만 확인함
    - 즉, 간접적인 효과를 제거하여 직접적인 LAG 관계를 측정하고 해석함

## 단어집 📓

| **용어** | **정의** |
| --- | --- |
| API 공식 문서 (Application Programming Interface) | 소프트웨어 구성 요소, 시스템 또는 서비스 간의 상호작용 방식과 데이터를 주고받는 규칙을 정의한 기술 문서 |
| Placeholder(플레이스 홀더) | 나중에 실제 데이터나 최적의 설정값으로 교체하기 위해 임시로 자리를 확보해 둔 요소나 기본값 |
| NDCG(Normalized Discounted Cumulative Gain) | 추천/검색 결과의 순서 품질을 측정하는 지표로, "상위에 관련성 높은 항목이 올수록 높은 점수"를 부여함 |
| Dickey-Fuller Stationary test(디키-풀러 정상성 검증) | 시계열 데이터의 정상성 여부를 통계적(p-value)으로 확인하는 검정 방법 |
| Stationarity(정상성) | 시간의 흐름에 따라 평균과 분산이 일정한 상태. 시계열 예측의 전제 조건 |
| LAG(시차) | 현재 시점($t$)을 기준으로 과거의 특정 시점($t-k$)과의 시간적 간격 또는 그 시점의 데이터 값 |
| ACF(AutoCorrelation Funtion, 자기상관함수) | 현재 시점과 과거 시점 간의 전체적인 상관관계 (간접적인 영향 포함) |
| PACF(Partial AutoCorrelation Funtion, 편자기상관함수) | 중간 시점을 제거하고 두 시점 간의 직접적인 상관관계만 측정하는 지표 |
| Interpolation(문자열 보간) | f-string 등을 활용해 문자열 내에 변수를 삽입하는 방식 |
| Trend Decomposition(추세 분해) | 시계열 데이터를 추세, 계절성, 잔차로 분리하여 시각화하는 기법 |
| Reproducibility(재현 가능성) | 동일한 데이터와 코드로 언제든 같은 결과를 얻을 수 있는 상태 |
| Code Snippet(코드 스니펫) | 특정 기능을 수행하는 재사용 가능한 작은 코드 조각, 자주 반복되는 작업을 빠르고 정확하게 구현하기 위해 미리 작성해 둔 코드 블록 |
| Hard Coding(하드 코딩) | 데이터를 코드 내부의 변수나 상수에 직접 입력하는 방식 |
